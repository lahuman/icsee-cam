# AI 에이전트와 함께 설치하기

터미널 명령이 익숙하지 않다면, 프로젝트 파일을 읽고 로컬 명령을 실행할 수 있는 AI 에이전트에 설치를 맡길 수 있습니다. AI가 실행 환경 확인·의존성 설치·오류 진단을 돕고, 사용자는 비밀번호 입력과 실제 영상 확인을 담당합니다. 채팅만 가능한 AI를 사용한다면 안내받은 명령을 직접 실행해야 합니다.

이 안내는 [처음 설치하고 카메라 등록하기](GETTING-STARTED.md)의 보조 가이드입니다. 먼저 프로젝트를 내려받고 AI에서 해당 폴더를 여세요. 카메라와 컴퓨터는 같은 로컬 네트워크에서 통신할 수 있어야 합니다. 카메라 IP와 로그인 ID를 준비하고, 지원 여부는 [지원 장비](../README.md#지원-장비)를 확인하세요.

## AI에 복사해서 요청하기

아래 요청문에서 카메라 IP와 로그인 ID만 자신의 값으로 바꾸세요. 비밀번호는 채팅에 적지 않습니다. IP를 모르면 공유기의 연결 기기 목록이나 카메라 앱의 장치 정보에서 확인하세요.

```text
이 프로젝트를 내 컴퓨터에 설치해서 카메라 실시간 영상을 볼 수 있게 도와줘.

카메라 IP: <카메라의 사설 IPv4 주소>
카메라 로그인 ID: <카메라 로그인 ID>
설치 방법: Docker Compose 우선, 사용할 수 없으면 Python 방식 검토
목표: 이 컴퓨터의 브라우저에서 로그인하고 실시간 영상 확인

README.md, docs/GETTING-STARTED.md, docs/AI-SETUP.md를 먼저 읽고
현재 OS, Docker Compose 또는 Python, ffmpeg/ffprobe와 포트 사용 상태를 확인해줘.
기존 설치가 있으면 현재 상태부터 확인하고, 처음 설치할 때는 별도 설치 공간을 사용해줘.

가능한 설치와 점검은 직접 진행하되, 비밀번호 입력이 필요하면
내가 내 터미널에서 실행할 정확한 명령과 작업 폴더를 알려줘.
카메라 비밀번호와 새 웹 비밀번호는 채팅으로 요청하지 말고
setup의 숨김 입력과 ICSEE_PASSWORD 환경 변수로 내가 직접 입력하게 해줘.
별도 터미널의 환경 변수가 네 실행 환경에 전달됐다고 가정하지 마.

설치 순서는 setup → doctor → register → serve로 진행해줘.
새 Docker 설치는 compose.quickstart.yaml을 명시하고,
Python 설치는 ICSEE_PROJECT_DIR을 프로젝트 내부 starter 폴더로 지정해줘.
운영용 compose.yaml이나 기존 계정·데이터·검증 프로필을 덮어쓰지 마.

이번 요청은 영상 확인까지야. 모터 이동, verify-motion, 프리셋 이동,
스피커·마이크 송출, 자동 추적 설정 변경, 시간 동기화,
자동 타임랩스와 외부 인터넷 공개는 실행하지 마.
검증 기록을 직접 만들어 방향 제어를 활성화하지 마.

오류가 나면 비밀번호나 세션 값을 출력하지 말고 필요한 부분만 진단해줘.
완료 시 접속 주소, 실행·중지·재시작 명령, 설정·데이터 저장 위치와
실제로 확인한 항목 및 내가 확인할 항목을 알려줘.
```

## 비밀번호 입력 단계

카메라 로그인과 이 프로그램의 웹 로그인은 별개입니다. `setup`에서 새 웹 관리자 계정을 만들고 비밀번호를 숨김 입력합니다. 카메라 비밀번호는 `ICSEE_PASSWORD`로 실행 시 전달하며 설정 파일에는 저장하지 않습니다. AI가 대화형 터미널을 사용자에게 넘길 수 없다면, 아래 단계는 사용자가 직접 진행하세요.

Docker 이미지를 빌드한 뒤 프로젝트 폴더의 사용자 터미널에서 실행하는 예입니다.

```sh
docker compose -f compose.quickstart.yaml run --rm web setup
```

이어서 **같은 터미널**에서 카메라 비밀번호를 입력합니다. 사용하는 셸에 맞춰 하나를 선택하세요.

```sh
# macOS 기본 zsh
read -rs 'ICSEE_PASSWORD?Camera password: '; echo
export ICSEE_PASSWORD
```

```bash
# bash
read -rsp 'Camera password: ' ICSEE_PASSWORD; echo
export ICSEE_PASSWORD
```

그 터미널에서 다음 명령을 한 줄씩 실행하고, 실패하면 다음 단계로 넘어가지 마세요.

```sh
docker compose -f compose.quickstart.yaml run --rm web doctor
docker compose -f compose.quickstart.yaml run --rm web register
docker compose -f compose.quickstart.yaml up -d web
```

기본 접속 주소는 [http://127.0.0.1:8000](http://127.0.0.1:8000)입니다. `setup`에서 만든 웹 계정으로 로그인하고 실제 영상이 나오는지 확인하세요. 8000 포트를 사용 중이면 위 명령 실행 전에 `export ICSEE_PORT=8001`을 설정하고 [http://127.0.0.1:8001](http://127.0.0.1:8001)을 사용하세요. 이후 명령에서도 같은 포트 설정을 유지합니다.

다른 터미널에서 서버를 재생성하면 비밀번호와 변경한 포트를 다시 설정해야 합니다. AI에게는 “같은 터미널에서 실행했고 doctor/register가 성공했다”처럼 결과만 알려주세요. 환경 변수 전체, `docker compose config`, `docker inspect` 출력이나 인증 파일을 채팅에 붙여넣지 마세요. 컨테이너 환경 변수에는 카메라 비밀번호가 들어 있습니다.

Python 방식은 [설치 가이드의 방법 B](GETTING-STARTED.md#방법-b-python으로-실행)를 따릅니다. AI가 준비한 가상환경을 사용하고, 사용자 터미널에서 `ICSEE_PROJECT_DIR`과 `ICSEE_PASSWORD`를 설정한 뒤 `setup`, `doctor`, `register`, `serve`를 실행합니다. 기존 환경 변수를 출력하거나 셸 초기화 파일에 비밀번호를 추가할 필요는 없습니다.

## 에이전트가 따라갈 진행 순서

1. **환경 확인:** 프로젝트 경로와 OS, 사용 가능한 실행 도구, 기존 설정·실행 서비스와 포트 충돌을 확인합니다. `.venv`, `config`, `starter` 또는 Docker 볼륨이 이미 있으면 재사용 가능 여부를 확인합니다. 계정 파일의 비밀번호·해시와 환경 변수 값은 출력하지 않습니다.
2. **설치 방식 선택:** Docker Compose를 사용할 수 있으면 새 설치용 `compose.quickstart.yaml`을 사용합니다. Python 방식은 Python 3.10 이상과 `ffmpeg`, `ffprobe`가 필요합니다. 기존 실제 운영 검증 환경은 macOS ARM64이며 다른 OS·구성의 동작을 확인 없이 보장하지 않습니다. 시스템 도구 설치가 필요하면 사용자의 OS에 맞는 방법으로 안내합니다.
3. **설치와 설정:** Docker 이미지를 빌드하거나 프로젝트 가상환경에 의존성을 설치합니다. Python 새 설치에는 `ICSEE_PROJECT_DIR="$PWD/starter"`를 적용합니다. 사용자에게 작업 폴더와 숨김 입력 명령을 전달합니다. 대화형 입력을 자동 생성하거나 비밀번호를 명령 인수·소스·파일에 넣지 않습니다.
4. **점검과 등록:** `doctor`의 `ready`와 실패 항목을 확인한 뒤 `register` 결과를 확인합니다. `doctor`는 카메라에 접속하지 않습니다. `register`는 인증과 장비 식별만 확인합니다. 인증 실패 시 반복 시도하거나 비밀번호를 추측하지 말고 사용자에게 ID·비밀번호 재확인을 안내합니다.
5. **영상 확인:** 서버를 실행하고 `/healthz`로 HTTP 응답을 점검합니다. 이 응답만으로 카메라 영상 성공을 판정하지 않습니다. 사용자가 직접 로그인해 영상이 갱신되는지 확인해야 합니다. AI가 원격 컴퓨터에서 작업 중이면 `127.0.0.1`은 서버 컴퓨터를 가리킵니다. 접속 방법을 먼저 설명하고 포트를 임의로 외부에 공개하지 않습니다.
6. **사용 방법 전달:** 실제 선택한 경로·포트에 맞춰 실행, 중지, 재시작 명령과 저장 위치를 안내합니다. Docker 설정·데이터는 `starter-config`, `starter-data` Compose 볼륨에, Python 새 설치는 `starter/config/`, `starter/data/`에 저장됩니다. 볼륨을 삭제하는 `down -v`나 `volume prune`으로 문제를 해결하지 않습니다.

설치 실패를 해결하려고 장비의 펌웨어·네트워크·계정 설정을 바꾸거나 기존 검증 프로필을 편집하지 않습니다. 필요한 진단은 사용자가 지정한 카메라를 대상으로 수행하고, 보고서를 공유하기 전에 주소·식별 정보와 자격증명이 포함됐는지 확인합니다.

## 완료 확인과 다음 단계

설치가 끝나면 다음 결과를 구분해 안내받으세요.

| 확인 항목 | 완료 기준 |
| --- | --- |
| 로컬 설치 | `doctor`의 `ready: true` |
| 장비 등록 | `register`의 `registered` 또는 `already_registered` 상태 |
| 웹 서버 | 선택한 로컬 주소의 `/healthz` 응답 확인 |
| 웹 로그인 | 사용자가 새 웹 계정으로 로그인 성공 |
| 실제 영상 | 사용자가 카메라 영상의 갱신을 확인 |
| 방향 제어 | 최초 설치에서는 미검증 상태. 영상 설치 완료와 구분 |

방향 제어가 필요하면 영상 확인을 마친 뒤 [방향 제어 활성화](GETTING-STARTED.md#방향-제어-활성화-선택-사항)를 별도로 진행하세요. `verify-motion`은 실제 모터를 움직입니다. 각 방향의 `MOVE`, 실제 관찰 방향, `STOP` 입력은 카메라를 직접 보는 사용자가 담당합니다. AI가 관찰 결과를 추측하거나 입력을 대신 완료해서는 안 됩니다.
