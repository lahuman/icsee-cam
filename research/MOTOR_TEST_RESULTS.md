# 실제 모터 검증 기록 — 2026-10-25

모터 테스트 승인은 사용자의 “프로토콜을 확인하고 모터 움직임 등을 테스트” 요청에서 받았습니다. 이후 사용자가 재시험과 왼쪽 3초 이동을 명시적으로 요청했습니다. 자동 반복 이동은 하지 않았습니다.

| 시험 | 파라미터 | 장비 응답 | 실제 관찰 |
| --- | --- | --- | --- |
| ONVIF 우/좌/상/하 | 속도 0.2, 각각 0.5초, 장비 timeout 1초 | ContinuousMove/STOP 정상 | 재시험 후 사용자 “움직이지 않았음”; 구도 변화만으로 이동이라고 판단한 설명은 철회 |
| DVRIP 최신 형태 | Preset=65535, Pattern=Start, Step1, 우 0.5초 | 이동/STOP Ret100 | 사용자 움직임 미확인 |
| DVRIP 캡처 형태 | Preset=65535, Pattern=SetBegin, POINT 포함, Step1, 우 0.5초 | 이동/STOP Ret100 | 사용자 움직임 미확인 |
| DVRIP v4.3.0 형태 | Preset=0, Pattern=Start, Step2, 우 0.5초 | 이동/STOP Ret100 | 사용자가 짧아서 구분하기 어렵다고 설명 |
| **DVRIP v4.3.0 형태** | **Preset=0, Step2, 좌 3초** | **이동과 watchdog/finally STOP 정상** | **사용자 “왼쪽으로 움직이고 멈췄음”** |
| DVRIP 구형 CLI 우/상/하 | Preset=0, Step2, 각각 1초 | 모두 이동 및 두 STOP 정상 | 사용자 “일부 방향”, 이어 “위로 움직이는 건 확인”; 우/하 미확정 |

따라서 현재 기본 제어는 **DVRIP 구형 시작 값 Preset=0 / 기본 Step2**입니다. `camera-profile.json`에 host·장비·펌웨어와 사용자 확인 근거를 저장하며 실제 접속 장비와 비교합니다. 비밀번호나 세션은 포함하지 않습니다.

`physical_motion_verified: false`는 각 요청의 응답만으로 실제 움직임을 자동 판정하지 않는다는 뜻입니다. 사용자 관찰 검증은 별도 기록입니다. 일반 CLI는 기본 0.5초/최대2초를 유지하며, 좌3초만 사용자 요청에 따라 내부 명시 override를 사용했습니다.

장비는 ONVIF PTZ 좌표를 항상 0,0으로 보고하므로 실제 위치 확인에 사용하지 않습니다. ONVIF 스냅샷 요청과 RTSP 영상 수신은 정상입니다. 프리셋 목록은 비어 있으며 저장·이동은 시험하지 않았습니다.

웹 UI는 로컬 RTSP→MJPEG 영상 출력까지 실제 브라우저에서 확인했습니다. 실제 방향 버튼 조작은 사용자 관찰과 함께 추가 확인할 수 있도록 열어 두었습니다. 버튼을 누르지 않고 페이지를 여는 것은 모터를 움직이지 않습니다.

예외 시 STOP, 지연 응답 중 별도 연결 watchdog STOP, 버튼 해제 취소, 연결 중 해제된 요청의 늦은 시작 방지, 브라우저 해제 요청 유실 시 서버 2초 제한은 모의 테스트로 검증했습니다. 실제 카메라 네트워크 단절/전원 차단/프로세스 강제 종료는 시험하지 않았습니다. 이 DVRIP 방식에 장비 측 timeout은 확인되지 않아 STOP 전달 자체가 불가능한 단절에서 물리적 정지를 보장하지 않습니다.

## 웹 UI 사용자 확인

로컬 웹 UI 제공 후 사용자가 “이동은 확인했어!”라고 실제 이동을 확인했습니다. 웹 UI를 통한 모터 이동을 확인한 것으로 기록합니다. 이번 확인에 구체적인 방향 목록이나 버튼 해제 직후 정지 관찰은 포함되지 않았으므로, 모든 방향·정지 조건이 개별 검증됐다고 확대 해석하지 않습니다. 추가 모터 명령은 전송하지 않았습니다.
